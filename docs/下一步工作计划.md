### 1.2 Android 构建链：暴露 5 个真实阻塞（旧文档均未记录）

| # | 问题 | 实测根因 | 处置 |
| --- | --- | --- | --- |
| 1 | Gradle 8.7.0 过低 | Flutter 3.47.9 硬下限 **8.14.0**（`DependencyVersionChecker.kt` 的 `errorGradleVersion`） | ✅ 升 **8.14.3** |
| 2 | AGP 8.6.1 过低 | 硬下限 **8.11.1** | ✅ 升 **8.11.1** |
| 3 | Kotlin 实际为 2.0.0 | `settings.gradle` 写 1.9.24 但被插件内置值覆盖；硬下限 **2.2.20** | ✅ 升 **2.2.20** |
| 4 | JVM 内存崩溃 | 原配置 `-Xmx4G + Metaspace2G`；本机空闲 2~3G、页面文件固定 2G | ✅ 降至 `-Xmx1280m`/`512m`、`workers.max=1`、Kotlin 进程内编译 |
| 5 | 缺 NDK 27.0.12077973 | `path_provider_android 2.3.0+` → `jni` → C++/CMake 原生编译 | ✅ `dependency_overrides: path_provider_android: 2.2.23`（无 jni）规避 |

> **最终状态**：以上 5 项已全部修复，但 Android 打包**仍受阻于本机物理内存不足**
> （构建并发时 Dart VM 自身 `runtime/vm/zone.cc:95 Out of memory`）。
> 按用户决策：**Android 打包验证延后、单独执行**；功能验证统一走 Windows。

### 1.3 顺带清理的死依赖（`lib`/`test` 零引用）

`drift`、`sqlite3_flutter_libs`、`drift_dev` —— 移除后 `analyze` 依然零问题、182 测试依然全绿。

## 6. 验收门禁（每轮交付必跑）

**服务端**：
```
gofmt -l（仅改动文件应为空） → go build ./... → go test 分包 -count=1
```
> Windows 下全量 `go test` 易超 120s 被截断，必须分包跑，不得把截断当失败。

**前端 Web**：
```
cd web && npx tsc -b && npm run build
```
> 两者必须同时过（`vite.config.ts` 不在 tsc 编译范围，其错误只在 build 阶段暴露）。

**移动端（常规，Windows 模式）**：
```
cd harness_mobile
flutter analyze --fatal-infos --fatal-warnings   # 必须 No issues found
flutter test                                     # 必须 All tests passed
flutter build windows --debug                    # 必须产出 harness_mobile.exe
```

**移动端（Android，延后单独执行）**：
```
flutter build apk --debug   # 需先解决内存约束；构建链改动已就绪待复核
```
