## 4. 已知风险与遗留

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | **移动端从未编译过** | 首次 `flutter analyze` 可能报一批错误 | 预留足够修复时间，不要低估 |
| R2 | **D6 身份可伪造** | 客户端自报 `device_id` 可冒充 | N3 优先处理 |
| R3 | workspaces 三件套未接入 UI | `WorkspaceSwitcher` 仍可能用 mock 数据 | N2 时一并接线 |
| R4 | 本机无 Flutter SDK | 移动端所有验证无法进行 | 需你决定何时搭环境 |
| R5 | **子 Agent 步数易耗尽** | 本仓注释极详尽，子 Agent 常在读透阶段耗尽预算而无产出（本轮 A1 即如此） | 小范围施工主进程直接做更高效；仅大范围才委派 |
| R6 | ticket 内存表无独立 GC | 仅靠签发时顺手清理，长时间无签发则过期项滞留 | 已可接受（单条记录极小，重启即清空）；若将来量大再加定时器 |
| R7 | `decideApproval` 的降级校验依赖查库 | 存储抖动时 `TokenKind` 返回空串 → 放行（fail-open） | 属有意取舍：审批真正的安全边界在 `Gate.CheckDevice` + `strict_approval_device`，不在此处 |

## 5. 验收门禁（每轮交付必跑）

**服务端**：
```
gofmt -l（仅改动文件）→ go build ./... → go test 分包 -count=1
```
> Windows 下全量 test 易超 120s 被截断，必须分包跑，不得把截断当失败。

**前端**：
```
cd web && npx tsc -b && npm run build
```
> 两者必须同时过。`vite.config.ts` 不在 tsc 编译范围，其语法错误只在 build 阶段暴露。

**移动端**（环境就绪后）：
```
flutter analyze && flutter test
```
