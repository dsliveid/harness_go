## 1. 结论速览

1. **可行**：MCP / 插件只能提供「工具能力」，不能提供「页面级 UI 与状态」。demo 中真正不可外置的部分（会话、项目、消息、Run、审批、快照、事件、存储、统计日志、模型设置）恰好就是 `基础服务设计.md` 判据 1–5 认定的内核，两条路径结论一致，无冲突。
2. **需纠偏**：demo 是「功能全展开」的交互原型，33 条内置工具 + 5 个扩展入口（设置→工具 / 高级→工具 / 高级→MCP / 高级→技能 / 能力路线图）直接照搬会带来**常驻上下文膨胀 + 入口语义重叠 + 空壳功能**三类负担，与「稳定、不再大调整」直接冲突。
3. **缺口明确**：demo 相对「日常编码自用」尚有 8 项刚需缺口（见 §4），其中 **鉴权登录**（web 版必有）与 **会话检索** 属于必须在 M0/M1 补齐的硬缺口。
4. **风险可控**：插件化真正的风险不是「能不能接」，而是 4 条工程约束：stdio MCP 的进程安全边界、工具数上限与描述截断、工具清单变更破坏 prompt 前缀缓存、外部插件状态的可解释性（`unavailable` 必须显示缺什么）。四条在现有设计文档中均已覆盖，需落到验收项。

## 3. 冗余 / 需抽离清单（本次评估的核心产出）

| 处置 | 对象 | 理由 | 建议动作 |
| --- | --- | --- | --- |
| **删除** | 能力路线图（页面 + 高级弹窗页签） | 开发期产物，不是产品功能；`page` 状态在生产无入口（`setPage` 无调用方） | 移除 `RoadmapPage` 与 `page='roadmap'/'plugins'` 分支 |

## 5. 插件化可行性边界（三条硬约束）

1. **UI 不可外置**：MCP / 插件是「能力」通道，不是「页面」通道。凡是需要页面与状态的（快照面板、统计、日志、归档、主题），只能内核 HTTP API + 前端实现。这条决定了「其余功能全部插件化」必须收窄表述为「其余**能力**插件化」。
2. **状态机不可外置**：需要嵌套 Run、事件桥接、会话锁、跨表事务的能力（子 Agent、协作器、长任务、会话打包、SOP），插件只能是「工具外壳」，真身在基础服务。否则会出现「插件重启即丢 Run」的一致性问题。
3. **不可信即审批**：外部插件默认按 `write` 处理、`Risk` 只能声明得比内核更高（防自我降级）、`danger` 逐次确认不可永久放行 —— 这三条已能兜住「外置后风险外溢」。

### 5.1 需在实施中盯住的 4 个工程风险

| 风险 | 量化/表现 | 对策 |
| --- | --- | --- |
| **常驻上下文膨胀** | 33 条工具（描述 + JSON Schema）保守估算 3.3k–5k token 常驻，且每轮重算；15 条约 1.5k–2k | 默认注入 ≤18 条；`Description` ≤200 字符；`MaxOutput` 32KB 强制截断；工具总数上限 48 并告警 |
| **前缀缓存被破坏** | 启用/禁用插件改变 prompt 前缀，导致 provider 缓存全失效 | 工具清单变更「下一个 Run 生效」并显式提示，不即时热更 Spec |
| **stdio MCP 进程安全** | 服务端可起任意子进程；公网暴露即 RCE 面 | 仅 `local` / `server` 形态允许，`server` 需显式 `allow_stdio` + 命令白名单 + 工作目录与 env 限制 |
| **降级不可解释** | `unavailable` / `degraded` 若只显示灰点，用户会反复重试 | UI 必须显示「缺什么」（如未检测到 git / 未配置 image 模型），且不阻塞启动 |

## 6. 建议冻结的 v1.0 基础功能基线

### 6.1 内核基础服务（不可禁用，14 项）
会话与消息、Run 编排、模型与能力路由、上下文组装与压缩、工具注册表、审批与访问模式、存储与迁移、事件总线与 SSE、工作区与文件、快照与回滚、插件与 MCP 管理、配置、可观测与审计、鉴权与令牌。

### 6.2 默认注入工具（≤18 条）——【状态：暂缓执行，见 §9 D5】

> 2026-10-28 用户拍板：**工具暂不收敛**，保持 33 条全开现状。以下 18 条清单保留作为未来收敛时的参考基线，当前不执行、不改动设置页。
`read_file` `list_dir` `file_outline` `glob` `grep` `write_file` `edit_file` `run_command` `fetch_web_page` `todo` `create_plan` `update_plan` `read_plan` `list_plans` `record_memory` `read_memory` `list_skills` `run_skill`

> 相对 demo 的 33 条，裁掉：`switch_plan`（并入 `read_plan`）、子 Agent/子进程 8、决策 3、图片 2、`save_skill`（改为配置文件或技能编辑器写入，不常驻注入）。

### 6.3 内置可选插件（默认关，会话级开启）
`subagent`（8）、`decision`（3）、`image`（2）、`skill` 写入侧、`session-bundle`。

### 6.4 外置（MCP / HTTP）
`browser`（Playwright）、数据库、GitHub、PDF/CSV 等第三方生态能力；`decision` 亦可由 MCP 提供。

## 7. 「后续不再大调整」需要一次定死的 5 条决策

1. **工具契约冻结**：`Tool` / `Spec` / `Result` 三结构 + 风险四级 + 命名空间规则（`builtin` / `mcp:<server>` / `plugin:<name>`）不再演进式改动。
2. **扩展入口唯一**：只保留一个「扩展」页（三分区），不再新增第四套市场页。
3. **默认注入集冻结**：§6.2 的 18 条为 v1 上限，新增能力一律走可选插件或 MCP。
4. **不可外置清单写死**：§6.1 的 14 项服务 + 会话/项目/快照/统计日志 UI，任何「插件化」提案不得触碰。
5. **不做的明确列出**：临时空间（已下线）、成长反思（已下线）、WASM 运行时、长任务检查点、内存态断点续跑 —— 写明「不做」，避免反复回炉。

## 8. 验收口径

- 工具上下文成本：`CountChatRequest` 显示 tools 段 ≤ 2k token（默认配置）。
- 冷启动：任一插件 `unavailable` / `degraded` 时启动耗时不增加、HTTP 正常监听。
- 降级可解释：`unavailable` 项 100% 带具体缺失原因文案。
- 审批不越权：外置插件工具风险等级 ≥ 其 Manifest 声明，`danger` 不可被「完全访问」永久放行。
- 缺口闭环：§4 的 P0 三项（鉴权、会话检索、压缩链路）在 M1 验收。
